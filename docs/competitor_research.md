# Competitor Research — AI-Code / "Vibe Coding" Security Scanners

References: [../FINDINGS.md](../FINDINGS.md) · [../Roadmap.md](../Roadmap.md) · [plan.md](plan.md)

Researched 2026-09-17 via open web search. Goal: identify real, currently-operating SaaS products that compete with VibeAudit (a regex-based security scanner for AI-built/"vibe-coded" apps), confirm which are in good standing, catalog their features, and use the gap analysis to inform production-readiness priorities.

## Top-line finding

The "vibe coding security scanner" niche is **not nascent — it is already crowded and well-capitalized**. Every major AppSec incumbent (Snyk, Semgrep, SonarQube, Checkmarx, Wiz, GitHub) has pivoted messaging toward "securing AI-generated code," and at least one well-funded pure-play (Backslash Security, $27M raised) explicitly brands itself "the vibe coding security company." VibeAudit is entering a space with real, funded, shipping competitors on both ends:

1. Scrappy indie URL-scanners targeting the exact same Lovable/Bolt/Replit/Cursor audience.
2. Enterprise AppSec platforms racing to add "AI code" detection and **real** auto-fix PR generation — the exact feature VibeAudit currently only simulates (`app/api/fix/generate/route.ts`, see [Roadmap.md](../Roadmap.md#1-autonomous-pr-fix-engine--claimed-working-confirmed-not-implemented)).
3. **[Review]** Free, first-party substitutes the buyer already has: Supabase's own Security Advisor, Lovable's built-in security scan, and the coding agent that wrote the code (see [Table 3](#table-3--free-first-party-substitutes-added-in-review)). These are not vendors to beat; they are the "why would I pay for this" objection in every sales conversation.

## Synthesis

### (a) Which competitors are legitimate and worth benchmarking against

Ranked by relevance × legitimacy:

1. **Rafter** — closest architectural twin (GitHub app, source-level SAST+secrets, CI gate, plain-English fixes, AI-agent-friendly output); real independent reviews (4.8/5, 23 AppSumo reviews).
2. **Lovable's built-in scan (+ Wiz for enterprise)** — not a startup to "beat" but a market reality to plan around: if VibeAudit targets Lovable users, it competes with a free first-party scanner, and for enterprise Lovable customers, with Wiz. **[Review]** See Table 3.
3. **Backslash Security** — best-funded pure-play explicitly using "vibe coding security" as its category name; currently enterprise-first, which leaves a self-serve/SMB gap VibeAudit could occupy.
4. **DeepSource** and **Semgrep** — best evidence that a mid-market (not just enterprise) company can ship real autofix PRs profitably; good pricing/business-model comparables.
5. **UNPWNED, Vibe App Scanner, VibeEval, CheckVibe** — the volume competitors for "scan my AI-built app" search traffic; not architecturally sophisticated but who VibeAudit will actually be compared against by price-sensitive solo-founder buyers on Google/Product Hunt.
6. **Naming / trademark** — OX Security's productized "VibeSec" (trademark status unverified) and, more urgently, the promo video's use of "**Vanta Audit**": Vanta is a large compliance-automation vendor, and a product called "Vanta Audit" that sells SOC 2 certificates invites a trademark dispute. **[Review]** Run a USPTO/EUIPO clearance search on "VibeAudit" and retire every "Vanta Audit" asset.

The dozen-plus tiniest tools (SafeToShip, isitsecure.ai, Safe Vibe Codes, etc.) are legitimate (real, non-scam) but show weak traction (no reviews, shifting pricing, single-founder). They matter as evidence of *how commoditized* black-box URL/header/secret checks have become, not as strategic threats individually.

### (b) Table-stakes features nearly everyone has that VibeAudit currently lacks

- **GitHub Actions / CI-gate blocking** — Rafter, UNPWNED, Wiz, Semgrep, and GitHub itself all fail a PR/build on critical findings. VibeAudit's webhook sync updates a dashboard but doesn't gate CI.
- **Dedicated, high-volume secrets detection** — GitGuardian ships 420+ secret patterns plus historical git-log scanning and public-repo monitoring; VibeAudit's single CWE-798 regex rule is thin by comparison. Cheap, high-value expansion that stays inside VibeAudit's existing no-dataflow-needed model.
- **Supabase/Firebase/BaaS-specific checks** — nearly every niche competitor (Vibe App Scanner, VibeEval, SafeToShip, SymbioticSec) has dedicated RLS-misconfiguration and Firebase-rules checks, because that's the single most common real vulnerability class across Lovable/Bolt/Replit apps (one study found ~98% of scanned Supabase-backed apps had issues). VibeAudit has no BaaS-config-specific rule category — **highest-ROI gap** given it fits the existing regex/pattern architecture.
- **Dependency/SCA scanning** — Socket.dev, Snyk, Semgrep, GitHub Dependabot all check third-party package vulnerabilities and "slopsquatting"/hallucinated-package risk (a well-documented AI-code-specific failure mode: ~20% of AI-suggested packages don't exist). VibeAudit has no SCA component.
- **Real compliance certification, not fixture pages** — Aikido and others hold actual SOC2 Type II / ISO27001 certifications; VibeAudit's compliance dashboard is hardcoded fixture data with no real backend and no actual certification. A legal/trust risk if ever shown to enterprise prospects, not just a feature gap (see [Roadmap.md](../Roadmap.md#2-four-dashboard-pages--claimed-as-live-product-surfaces-confirmed-fixture-only)).
- **AI-code-provenance awareness** — SonarQube's "AI Code Assurance" (flag files as AI-authored, apply stricter rules to them) is low-effort, high-narrative-value, fits VibeAudit's existing deterministic-rules engine, and directly reinforces its "security for AI-built apps" positioning.
- **Suppression / baseline / ignore workflow** — **[Review]** every tool above ships `nosemgrep`-style inline ignores, a `.gitleaksignore`-style file, or a baseline that only fails on *new* findings. VibeAudit has none. This is a prerequisite for the CI gate, not a nice-to-have: without it, a gate that fails builds on the current `missing-auth`/`no-rate-limiting` heuristics (which only recognise Supabase auth calls and four rate-limit identifiers) will be disabled by the customer within days.

### (c) Genuinely differentiating / hard-to-replicate vs. easy wins

**Hard to replicate (real moats, multi-quarter+ engineering investment):**

- **Real AST/dataflow (taint) analysis** — Snyk's DeepCode, Endor Labs' AURI, Checkmarx, Qwiet/Harness's Code Property Graph, and GitHub's CodeQL all do genuine source-to-sink tracing. This is the single biggest capability gap between VibeAudit and the serious players. Multiple sources (including an academic paper testing a VibeSec-style architecture) specifically call out that plain regex/Semgrep-only approaches "produced zero vulnerability findings despite confirmed vulnerabilities" on AI-generated code's more architectural/logic-level bugs (client-side auth checks, plaintext password handling in localStorage, backwards authorization logic). This is a real, citable limitation of VibeAudit's current approach, not just a feature gap.
- **Real autonomous auto-fix PR generation with high accuracy** — Corgea (>90% claimed), Snyk (~80%), DeepSource, Semgrep Autofix (beta), and Mobb (a whole company built around just this) prove it's achievable, but it requires LLM-based code generation + validation/testing loops + human-review UX — a materially different (and costlier, since it reintroduces LLM inference cost) engineering investment than VibeAudit's current zero-LLM-cost deterministic explanations. This is precisely the feature VibeAudit currently simulates; multiple direct competitors have already shipped the real version.
- **Native platform integration** (Wiz-in-Lovable) — extremely hard to replicate without a partnership; a distribution moat, not a technical one.

**Easy wins (fit VibeAudit's existing regex/deterministic architecture, no LLM cost required):**

- Supabase RLS / Firebase rules / BaaS-config-specific rule pack (highest ROI given documented prevalence).
- Expanded secrets-pattern library (hundreds of patterns like GitGuardian, still regex-based).
- Git-history secret scanning (not just current-state file scanning).
- Security-headers/CORS/CSRF checks (nearly free to add, everyone else has them).
- Basic SCA / dependency-CVE lookup against a public vulnerability database (no AST needed — parse lockfiles + a CVE feed) — also covers the "hallucinated package"/slopsquatting angle.
- "AI Code Assurance"-style provenance flagging (git blame / commit-message heuristics to flag likely-AI-authored files) — cheap, on-brand, copies Sonar's approach.
- CI/CD gate (GitHub Actions check that fails the build on critical findings) — mechanically straightforward given VibeAudit already has GitHub App + webhook infrastructure.

### (d) Unit economics of real autofix — added in review

The research above establishes that real auto-fix PRs are table stakes among funded competitors, but doesn't cost them. Every "real" implementation in Table 2 runs an LLM per fix: Semgrep Autofix requires Amazon Bedrock with Anthropic models (verified in Semgrep's beta docs), Corgea prices at ~$39/developer/month, DeepSource at $24/seat. VibeAudit's Pro plan is **$29 flat with unlimited scans and unlimited fix PRs** (`lib/stripe/plans.ts`). The moment the fix engine is real, one power user opening fixes across a 400-file repo can cost more in inference than the plan earns. Before building the fix engine, decide on metering: per-fix credits, a monthly included budget with top-ups (the direction [checklist.md](checklist.md) already leans), or a per-repo cap. The pricing page is a competitive vulnerability, not just a billing detail.

### (e) Black-box URL scanning — deferral revisited in review

Section (c) treats URL-based scanning as commoditized. That is true of the *checks* (headers, TLS, exposed files), but the *mode* is what makes half of Table 1 viable for this audience: a non-technical founder has a deployed URL and often cannot (or will not) install a GitHub App on a repo they don't fully understand. Rafter and VibeSec are the only source-level tools in the niche tier; everyone else is URL-first for a reason. Keep the deferral in [implementation_plan.md](implementation_plan.md) as a scoping decision, but treat "no URL mode" as a go-to-market gap for the stated target buyer, not a feature nicety.

### Bottom line for roadmap planning

VibeAudit's realistic, defensible near-term positioning is **"the deterministic, zero-LLM-cost, fast, cheap, source-integrated scanner for the most common AI-generated-app vulnerability classes"** — competing on speed/cost/simplicity against the fragmented niche tier (Table 1) — while being explicit (internally and eventually to customers) that the Autonomous PR Fix Engine, Fleet/Analytics/Compliance dashboards, and continuous re-scan-on-webhook are not yet real. Several funded competitors (Corgea, Snyk, Semgrep, Aikido, Mobb, GitHub itself) have already shipped genuine versions of exactly those features and would expose the gap quickly in any side-by-side eval or due-diligence review. See [plan.md](plan.md) Phase 2/3 for where these items currently sit and consider re-prioritizing the "easy wins" above ahead of the higher-effort claim-alignment items. **[Review]** Before any of the easy wins ship, the prerequisites recorded in [implementation_plan.md Part 0](implementation_plan.md#part-0--prerequisites-surfaced-in-review) (installation-scoped repo fetch, suppression/baseline, scoring revision) must land; two of them are live security gaps, not features.
